**Goal:** Replace the two forked packages `pystorm==3.1.4+a8c.1` and `streamparse==5.0.0+a8c.1` with a single slim package, `pystorm-a8c`, containing only the codepaths casterisk-realtime actually uses — build a topology JAR, and submit it to a Nimbus RPC host:port.

**Architecture:** One repo, one package, one version. The merged library is developed on a branch of the existing a8c fork `Automattic/pystorm`, not in a new repository — that keeps the protocol core's history and its 65 tests, and leaves `master` free to track upstream. The merge collapses the two-layer component hierarchy (`pystorm.Bolt` ← `streamparse.storm.Bolt`) into single classes, drops every SSH/remote-management codepath, and reduces the runtime dependency set from seven packages to one (`thriftpy2`). The Storm 1.x Thrift IDL is isolated behind a facade module so a future Storm 2.x swap is a contained change.

**Tech Stack:** Python 3.9+ (CI-tested through 3.14 via `uv`), `thriftpy2` for Nimbus RPC, Apache Storm 1.2.x multi-lang protocol over stdin/stdout, stdlib `zipfile` for JAR assembly (no JVM build tooling), `uv_build` (uv's own PEP 517 backend) for packaging.

## Context

### Why

`casterisk-realtime` is a pure-Python Storm system. It reaches Storm through two Automattic forks — `Automattic/pystorm` (the multi-lang protocol layer, 1,599 LOC) and `Automattic/streamparse` (topology DSL + CLI, ~6,972 LOC). Together that is **~8,571 LOC and 7 runtime dependencies**, of which casterisk uses a small fraction.

Four problems drove this work:

1. **The fork carries enormous unused surface.** Nine of thirteen CLI subcommands (`list`, `tail`, `stats`, `quickstart`, `update_virtualenv`, `remove_logs`, `slot_usage`, `worker_uptime`, `visualize`) are invoked nowhere in any Parse.ly repo. `examples/` alone is 273 files / ~36,000 LOC of vendored Chef cookbooks. `JavaBolt` and `JavaSpout` have zero consumers. (`BatchingBolt` also has zero consumers but is deliberately kept — see Task 4.)
2. **Two repos, one logical change.** Every pystorm fix requires a coordinated streamparse version bump and a second devpi publish (`docs/Ops and Architecture Documentation/Storm/pystorm-and-streamparse.md:52`).
3. **Python/Storm upgrades are blocked.** The forks still carry `six`, `simplejson`, `from __future__`, `io.open` Python-2 branches, and a `tox.ini` listing `py27`–`py37`. Workers are pinned to Python 3.9, which is near EOL.
4. **No control over the protocol layer.** casterisk monkey-patches around the library rather than through it: `casterisk/spouts/common/base.py` uses `__init_subclass__` to wrap every subclass's `next_tuple` just to gauge `len(self.unacked_tuples)`, and reaches into `self.task_id` and pystorm's `max_fails` attribute name directly.

### Intended outcome

A single `pystorm-a8c` package of roughly **3,100 LOC with one runtime dependency**, providing exactly: the runtime component classes casterisk subclasses, the topology DSL, a `submit` command that talks directly to Nimbus over Thrift, and a `jar` command that zips the topology source with the stdlib. No SSH, no JVM build toolchain, no worker virtualenv management, no Storm UI scraping, no project scaffolding, no remote debugger.

### The evidence this plan is built on

A sweep of every repo under `<repos>/` established that `casterisk-realtime` is the **only** real consumer. `engineering/solutions` pins both packages transitively (via `casterisk==2026.5.1.1777659029`) but imports neither. `dash`, `dash-assist`, `mage`, `ML`, `parsely-js`, `parselyutils`, `parselydeploy`, `parsely-utility-scripts` have zero references. Within the monorepo, `ansiform`, `rundeck`, `deploymint`, `monitoring`, `conversions`, `api`, `_docker`, `localdev.docker` and all others are clean.

**Actively used surface — the complete list.** Nothing outside this needs to be ported.

### Two risks that are not free deletions

**Risk 1 — removing Fabric breaks the legacy deploy route, by design.** `<deployments>/deploy.sh:165` runs `fab "$ENVIRONMENT" deploy.topo:"$CASTERISK_REALTIME_TOPOLOGY"`, reaching `casterisk/tasks/deploy.py`, which shells out to `sparse jar -s` / `sparse submit` and depends on `fabric.api`, `streamparse.util.activate_env`, and `streamparse.version.__version__`. The same script installs `casterisk-realtime/requirements.txt` into the venv it then runs `fab` from (`deploy.sh:142`), so **the legacy route and the new route share one requirements file** — dropping the `streamparse` pin and deleting the fabfile takes that route out with them.

That is the intended outcome, not a hazard to mitigate. `pystorm-a8c` targets exactly one cluster, `<nimbus-host>` (env `storm4`), which has no SSH or Fabric access; the SSH-era clusters `storm3` / `storm-dev3` are not targets. Deploys reach `storm4` through the deployer container's `bin/topo-submit` (`deployer.Dockerfile:22`), which never shells out to `fab`. Task 14 therefore deletes the Fabric path outright rather than negotiating a transition period.

The consequence to hand off, not to solve here: once Task 14 lands, `deploy.sh`'s `fab ... deploy.topo` branch is dead code for `casterisk-realtime`. Removing it is a follow-up PR in the `deployments` repo (Task 14 Step 9), and it does not block this work — nothing in `pystorm-a8c` or the `storm4` path reads it.

**Risk 2 — the two tunnelling envs are retired, not ported.** Neither `storm3` nor `storm-dev3` sets `use_ssh_for_nimbus` in `casterisk-realtime/config.json`, and `streamparse/util.py:360` defaults it to `True` — so both reach Nimbus through an SSH tunnel today. Rather than carry a tunnel forward for them, Task 14 Step 8 deletes both env blocks: they are not targets for this package. `local` and `storm4` (`<nimbus-host>:6627`, the sole cluster target) already set the key to `false` and use the blobstore venv path, so **no env that survives ever tunnelled**. The library still accepts a stale `use_ssh_for_nimbus` key and warns rather than crashing, so an unmigrated config fails loudly at the right place instead of silently connecting somewhere unexpected.

## Global Constraints

Exact values, applying to every task:

- Distribution name: **`pystorm-a8c`**. Import package: **`pystorm_a8c`**.
- Home: a branch named **`pystorm-a8c`** on **`github.com/Automattic/pystorm`** (the existing a8c fork). Not a new repository. `master` stays where it is so upstream can still be tracked/merged.
- `requires-python = ">=3.9"`. CI matrix: **3.9, 3.10, 3.11, 3.12, 3.13, 3.14**, run via `uv`.
- **Exactly one runtime dependency: `thriftpy2>=0.4.11`.** Adding any other runtime dependency requires explicit sign-off. Removed for good: `six`, `simplejson`, `Fabric39`, `paramiko`, `requests`, `texttable`, `jinja2`, `ruamel.yaml`, `setuptools`/`pkg_resources`, `msgpack`, `cython`, `graphviz`.
- Target Storm: **1.2.x**. Both clusters this package actually talks to run **1.2.3**: the sole prod target `<nimbus-host>` (`storm4`), and the local cluster used for the Task 15 smoke test, pinned at `_docker/storm/Dockerfile:19` (`STORM_VER='1.2.3'`).

  Do not cite `ansiform/ansible/roles/storm/defaults/main.yml:7` for this. It reads `storm_version: 1.2.2`, but that is an inert Ansible default that is always overridden before install: `roles/storm/tasks/parameters.yml:9-19` sets the version from the distro release — `1.2.2` only on Ubuntu Bionic, `1.2.3` on Jammy and Noble. `roles/storm/tests/test_role.py:6` asserts exactly that mapping (`{"18.04": "1.2.2", "20.04": "1.2.3", "22.04": "1.2.3"}`), and is the file to read if you want the effective version rather than the default. Some inventories also pin it directly — `group_vars/storm_dev2.yml:6` and `storm_dev3.yml:6` both set `1.2.3` — though `parameters.yml`'s `set_fact` outranks group_vars either way. Three layers, and only the bottom one says 1.2.2.

  **Nothing in this plan changes because of 1.2.2 vs 1.2.3.** Both are the same Storm minor line, and the two interfaces this package depends on — the multi-lang protocol over stdin/stdout and the Nimbus Thrift IDL — are identical across 1.2.x patch releases. The target is the *minor* line, which is why `STORM_IDL_VERSION` is `"1.x"` and not a full version string. Patch-level drift within 1.2.x is not a compatibility event for this package and should not be tracked as one.

  The Thrift IDL must be isolated so Storm 2.x is a contained swap. The `storm-core`/`flux-core` Maven deps in `casterisk-realtime/project.clj` are *not* a constraint — they were only ever a classpath for a thin JAR that ships no Java (Task 11), and `project.clj` is deleted.
- Serializer: **JSON only**, stdlib `json`. The pluggable-serializer indirection is removed.
- Worker entry-point console script: **`pystorm_a8c_run`** (replaces `streamparse_run`).
- **Deployment target: exactly one cluster** — `<nimbus-host>:6627`, the `storm4` env — reached over direct Nimbus Thrift from the deployer container's `bin/topo-submit`. It has no SSH or Fabric access. The SSH-era `storm3` / `storm-dev3` envs are not targets and are deleted (Task 14 Step 8).
- **A `streamparse` compatibility shim ships inside this distribution, and is temporary.** It exists only so downstream code that still says `from streamparse import Bolt` keeps working during migration. Every access emits `DeprecationWarning`. It is explicitly scheduled for deletion — the removal checklist is the module docstring of `streamparse/__init__.py` (Task 12 Step 3c), restated for downstream readers in the README (Task 12 Step 5) and for operators in Task 15 Step 9. **Consequence: `pystorm-a8c` and the real `streamparse` package must never be installed together** — they both own the top-level `streamparse` name. Task 14 removes the old pin in the same commit that adds this one.
- **No JVM build toolchain.** The topology JAR is assembled with stdlib `zipfile`; no `lein`, no `javac`, no `maven`, no JDK is required to build or submit. See Task 11 for why a pure-Python topology JAR contains no Java.
- **No SSH and no Fabric anywhere, in the library or in its usage path.** No `subprocess` invocation of `ssh`, no `paramiko`, no `fabric`/`fabric39`, no `fab` entry point, no fabfile. Enforced in the library by the source scan in Task 9 and the dependency audit in Task 12, and in casterisk-realtime by Task 14 Step 9, which deletes `fabfile.py`, `tasks.py`, and the `casterisk/tasks/` deploy modules outright.
- CLI exposes **exactly two** subcommands: `submit` and `jar`.
- Version lives in exactly one place: the literal `version` field in `pyproject.toml`. `pystorm_a8c.__version__` is *derived* from it at import time via `importlib.metadata.version("pystorm-a8c")` — the `uv_build` backend rejects `dynamic = ["version"]`, so this is the direction that keeps one source of truth. Start at **`1.0.0`** — a plain PEP 440 release, no epoch and no local label. The distribution name `pystorm-a8c` already distinguishes this from upstream `pystorm`, so a `1!` epoch would order nothing that is ever compared and a `+a8c` label would restate what the name says. The retired `+a8c.N` suffix scheme exists only on the old `pystorm`/`streamparse` dist names.

  | Segment | Value | Means |
  |---|---|---|
  | Major | `1` | Compatible with **Apache Storm 1.x**. Storm 2.x support ships as `2.0.0`. |
  | Minor | `.0` | Feature and breaking Python-API changes within a Storm major line. |
  | Patch | `.0` | Fixes. |

  Consequence worth stating plainly: **the major version is spoken for by Storm compatibility**, so breaking changes to this package's own Python API go in the minor position, not the major one. Say so in the README — it is the one thing a reader will get wrong.
- Publish target: internal devpi, `TWINE_REPOSITORY_URL=https://<internal-index>/`, `UV_INDEX_URL=https://<internal-index>/+simple`.
- Code style: `black` (the pystorm fork is already black-formatted as of commit `0f853e0`).

**Why `uv_build` and not `hatchling`.** `uv_build` is uv's own PEP 517 backend, so the entire toolchain — venvs, the 3.9-3.14 test matrix, locking, building — is the single `uv` binary with no separate build-time dependency tree. It is a normal PEP 517 backend, so this does **not** force anyone to use uv: `pip install` against the sdist fetches `uv_build` from PyPI and builds it fine.

`module-root = ""` is required. `uv_build` defaults to a `src/` layout; this package is flat (`pystorm_a8c/` at the repo root), and omitting the key fails the build with a "module not found" error rather than silently shipping an empty wheel.

`module-name` is a **list** because this distribution ships two top-level packages: `pystorm_a8c` and the deprecated `streamparse` shim (Task 12). Dropping `streamparse` from that list is the last step of retiring the shim.

The upper bound in `requires` is deliberate — `uv_build` tracks uv's own release cadence, so an unbounded pin would let a future major bump change build behavior silently. Widen it consciously when upgrading uv.

**The one thing this backend costs us:** `uv_build` does not support `dynamic = ["version"]`. The version must be a literal in `pyproject.toml`, which inverts where the single source of truth lives — see Step 5, where `__init__.py` derives `__version__` from installed metadata rather than declaring it.

Note: `--doctest-modules` is deliberately **not** carried over from the old `setup.cfg`. It caused pytest to import every module at collection time, which is how a stray `import fabric` could break collection for unrelated tests.

```python
import io
import json
import logging

from pystorm_a8c.exceptions import StormWentAwayError

log = logging.getLogger(__name__)


class JSONSerializer:
    """Storm multi-lang JSON line protocol.

    Messages are newline-delimited JSON terminated by a line containing
    exactly ``end``.
    """

    def __init__(self, input_stream, output_stream, reader_lock, writer_lock):
        self.input_stream = self._wrap_stream(input_stream)
        self.output_stream = self._wrap_stream(output_stream)
        self._reader_lock = reader_lock
        self._writer_lock = writer_lock
        self._blank_lines_read = 0

    @staticmethod
    def _wrap_stream(stream):
        """Reopen a stream in UTF-8 text mode."""
        if hasattr(stream, "buffer"):
            return io.TextIOWrapper(stream.buffer, encoding="utf-8")
        if hasattr(stream, "readable"):
            return io.TextIOWrapper(stream, encoding="utf-8")
        log.error("Could not wrap %r in a UTF-8 TextIOWrapper", stream)
        return stream

    def read_message(self):
        """Read one complete multi-lang message.

        :returns: a ``dict`` (a command) or a ``list`` (task IDs)
        :raises StormWentAwayError: if Storm closed the stream
        """
        message = []
        with self._reader_lock:
            while True:
                line = self.input_stream.readline()
                if not line:
                    raise StormWentAwayError()
                line = line.rstrip("\n")
                if line == "end":
                    break
                if line == "":
                    # Storm occasionally emits stray blank lines; count them so
                    # a pathological stream is visible without flooding logs.
                    self._blank_lines_read += 1
                    if self._blank_lines_read % 1000 == 0:
                        log.warning(
                            "Read %d blank lines from Storm",
                            self._blank_lines_read,
                        )
                    continue
                message.append(line)
        return json.loads("\n".join(message))

    def serialize_dict(self, msg_dict):
        """Serialize a message to the multi-lang wire format."""
        return f"{json.dumps(msg_dict)}\nend\n"

    def send_message(self, msg_dict):
        """Write a message to Storm.

        :raises StormWentAwayError: if the pipe is closed
        """
        serialized = self.serialize_dict(msg_dict)
        with self._writer_lock:
            try:
                self.output_stream.flush()
                self.output_stream.write(serialized)
                self.output_stream.flush()
            except IOError as e:
                raise StormWentAwayError() from e
```

Two behavior notes. `json.dumps` serializes a `namedtuple` as a JSON array by default because `namedtuple` subclasses `tuple` — that is exactly what `simplejson`'s `namedtuple_as_object=False` was buying, so the dependency drops with no wire-format change. And `serialize_dict` is now called *before* the lock is taken, so a serialization `TypeError` surfaces to the caller instead of being swallowed.

**Both batching classes are kept, and the upstream hierarchy is preserved verbatim** — `TicklessBatchingBolt(BatchingBolt)`, exactly as `pystorm/bolt.py:417` has it. An earlier revision of this plan flattened the two into one class on the grounds that casterisk subclasses only the tickless variant. That is still true, but the two differ in a way worth keeping available: `BatchingBolt` flushes on **Storm tick tuples** (`ticks_between_batches`, a count, requiring `topology.tick.tuple.freq.secs` to be configured), while `TicklessBatchingBolt` flushes on a **daemon timer thread** (`secs_between_batches`, wall-clock, no Storm config). Tick-driven batching is the right tool for a bolt that must not run a second thread, and deleting it forecloses that option for no gain.

Keeping both is also the *lower-risk* choice on this specific file, which is worth being explicit about since it inverts the usual "port less" default:

- **The MRO of all ten casterisk bolts stays byte-identical to today.** Flattening would have changed it; that was previously flagged in the Self-Review as a behavioral change to re-check at review. It is now a non-event.
- **`bolt.py` becomes a copy-and-fix rather than a refactor.** No methods move between classes, no base class changes, no tick machinery is unpicked. Every remaining edit in Step 3 is a local one.
- **The seeded `BatchingBoltTests` (10 tests, `test_bolt.py:357-580`) are kept wholesale** instead of being partly deleted and partly ported onto another class. More coverage, and no test surgery on the highest-risk file in the plan.

```python
import logging
import os

import thriftpy2
from thriftpy2.protocol import TBinaryProtocolFactory
from thriftpy2.rpc import make_client
from thriftpy2.transport import TFramedTransportFactory

from pystorm_a8c.storm import Nimbus

DEFAULT_NIMBUS_PORT = 6627
NIMBUS_ENV_VAR = "PYSTORM_A8C_NIMBUS"

log = logging.getLogger(__name__)

_storm_workers = {}


def get_nimbus_host_port(env_config):
    """Resolve the Nimbus RPC endpoint.

    ``PYSTORM_A8C_NIMBUS`` overrides config.json entirely.

    .. note::
       ``use_ssh_for_nimbus`` in config.json is accepted for backwards
       compatibility and ignored, but warns. Nimbus is always contacted
       directly. A stale config that still sets the key would otherwise
       look like it is tunneling when it is not.
    """
    if "use_ssh_for_nimbus" in env_config:
        log.warning(
            "use_ssh_for_nimbus is set in the env config and is ignored: "
            "pystorm-a8c always contacts Nimbus directly. Remove the key."
        )
    nimbus = os.environ.get(NIMBUS_ENV_VAR) or env_config.get("nimbus")
    if not nimbus:
        raise ValueError("No nimbus host specified in env config or environment")
    if ":" in nimbus:
        host, _, port = nimbus.rpartition(":")
        return host, int(port)
    return nimbus, DEFAULT_NIMBUS_PORT


def get_nimbus_client(env_config=None, host=None, port=None, timeout=None):
    """Open a Thrift RPC client against Nimbus."""
    if host is None:
        host, port = get_nimbus_host_port(env_config)
    return make_client(
        Nimbus,
        host=host,
        port=port,
        proto_factory=TBinaryProtocolFactory(),
        trans_factory=TFramedTransportFactory(),
        timeout=timeout,
    )


def get_storm_workers(env_config):
    """Return the list of supervisor hosts.

    Uses ``workers`` from config.json when present; otherwise asks Nimbus.
    """
    workers = env_config.get("workers")
    if workers:
        return workers
    host, port = get_nimbus_host_port(env_config)
    if (host, port) not in _storm_workers:
        client = get_nimbus_client(env_config, host=host, port=port)
        cluster_info = client.getClusterInfo()
        _storm_workers[(host, port)] = [s.host for s in cluster_info.supervisors]
    return _storm_workers[(host, port)]


def nimbus_storm_version(nimbus_client):
    """Return Nimbus's Storm version as a comparable tuple."""
    try:
        raw = nimbus_client.getVersion()
    except Exception:
        # Storm < 0.10.0 has no getVersion; treat as oldest supported.
        return (0, 0, 0)
    parts = []
    for chunk in str(raw).split("."):
        digits = "".join(c for c in chunk if c.isdigit())
        parts.append(int(digits) if digits else 0)
    return tuple(parts)
```

def parse_option(raw):
    """Parse a single ``-o key=value`` argument.

    Values are parsed as JSON when possible so ints, floats, bools and JSON

    key, sep, value = raw.partition("=")

    try:
        return key, json.loads(value)
    except ValueError:
        return key, value

### Why there is no `lein`, and no `javac` either

**A Storm topology JAR for a pure-Python topology contains no Java.** Four facts establish this, each checkable in the repo today:

1. **casterisk-realtime has no JVM source.** `find . -name '*.java' -o -name '*.clj' -o -name '*.scala'` returns exactly one hit — `project.clj` itself, which is a build descriptor, not source. `:aot :all` over `:source-paths ["topologies"]` therefore compiles nothing, because `topologies/` holds only `.py` files.
2. **The build is a *thin* jar.** `Makefile:40` runs `streamparse jar -s`, and `-s` means `lein jar`, not `lein uberjar` — dependencies are not bundled. `storm-core` and `flux-core` are declared only so `lein` can resolve a classpath it never ships.
3. **What little could leak in is excluded anyway.** `:jar-exclusions` in `project.clj` strips `org.apache.storm.*` (all but flux), `trident`, `*.yaml`, `log4j.properties`, and **`META-INF`** — so the JAR shipping to production today has no `MANIFEST.MF`. A manifest is not required, which is exactly why a plain ZIP is a drop-in.
4. **Flux is not on the submit path.** `FluxShellBolt` / `FluxShellSpout` appear only in `streamparse/dsl/topology.py:198,202`, inside `to_flux_dict`, which serves `run`/`visualize` — both dropped. Submission builds `ComponentObject(shell=ShellComponent(execution_command, script))`, a native Storm Thrift type handled by Storm's own `ShellBolt`/`ShellSpout`.

So the JAR's entire payload is `resources/**`: `streamparse/cli/jar.py:18` calls `prepare_topology()`, which copies `src/` to `_resources/resources/`, and `lein` zips it. The consumer is `run.py`, which appends `resources/` to `sys.path` before importing the component module (Task 8).

**A JAR is a ZIP.** Building it with `zipfile` from the stdlib removes `lein`, Leiningen's JVM startup, the `openjdk-11-jdk`/`maven`/`leiningen` apt installs in `deployments/deploy.sh:148`, the `LEIN_ROOT=1` workaround, `project.clj`, and the `_build`/`_resources` scratch directories. Measured on the real `casterisk-realtime/src` tree: **212 files, 1.0 MiB, 0.03 s.**

**The one trap.** `casterisk-realtime/src/casterisk` is a *symlink* to `../casterisk`. `pathlib.Path.rglob` does not descend into symlinked directories, so the obvious implementation silently produces an **empty JAR** that submits without error and fails at worker start. `os.walk(..., followlinks=True)` is mandatory, and Step 1 asserts it with a symlink fixture.

```python
"""Build a Storm topology JAR.

A topology JAR for a pure-Python topology carries no Java: its entire
payload is the ``resources/`` tree that Storm unpacks into the worker
directory and that ``pystorm_a8c.run`` adds to ``sys.path``. A JAR is a
ZIP, so the stdlib is the whole toolchain -- no lein, no JDK.
"""

import os
import pathlib
import zipfile

RESOURCES_ROOT = "resources"
EXCLUDED_DIRS = {"__pycache__", ".git", ".pytest_cache", ".mypy_cache"}
EXCLUDED_SUFFIXES = (".pyc", ".pyo", ".pyd")
EXCLUDED_NAMES = {".DS_Store"}

# A fixed timestamp keeps rebuilds byte-identical, which keeps the blobstore
# digest in bin/topo-submit stable across rebuilds of unchanged code.
# ZIP cannot store years before 1980.
_ZIP_EPOCH = (1980, 1, 1, 0, 0, 0)


def _collect(src_dir):
    """Yield (absolute_path, posix_arcname) pairs, following symlinks.

    ``followlinks=True`` is required, not stylistic: casterisk-realtime's
    ``src/casterisk`` is a symlink to ``../casterisk``, and os.walk skips
    symlinked directories by default -- which yields an empty JAR.
    """
    src_dir = pathlib.Path(src_dir)
    if not src_dir.is_dir():
        raise FileNotFoundError(f"source directory does not exist: {src_dir}")
    for root, dirs, files in os.walk(src_dir, followlinks=True):
        dirs[:] = sorted(d for d in dirs if d not in EXCLUDED_DIRS)
        rel_root = pathlib.PurePath(root).relative_to(src_dir)
        for name in sorted(files):
            if name in EXCLUDED_NAMES or name.endswith(EXCLUDED_SUFFIXES):
                continue
            arcname = pathlib.PurePosixPath(RESOURCES_ROOT, *rel_root.parts, name)
            yield os.path.join(root, name), str(arcname)


def build_jar(src_dir="src", output_path=None):
    """Zip ``src_dir`` into a topology JAR and return the output path."""
    if output_path is None:
        output_path = os.path.join(".artifacts", "topology.jar")
    output_path = pathlib.Path(output_path)
    output_path.parent.mkdir(parents=True, exist_ok=True)

    entries = list(_collect(src_dir))
    if not entries:
        raise RuntimeError(
            f"no files to package under {src_dir!r}. If it contains a symlink, "
            "note that only directories reachable with followlinks=True are "
            "walked -- an empty JAR submits successfully and then fails at "
            "worker start, so this is a hard error."
        )

    with zipfile.ZipFile(output_path, "w", zipfile.ZIP_DEFLATED) as zf:
        for abs_path, arcname in entries:
            info = zipfile.ZipInfo(arcname, date_time=_ZIP_EPOCH)
            info.compress_type = zipfile.ZIP_DEFLATED
            info.external_attr = 0o644 << 16
            with open(abs_path, "rb") as fh:
                zf.writestr(info, fh.read())

    print(f"Topology JAR created: {output_path} ({len(entries)} files)")
    return str(output_path)


def subparser_hook(subparsers):
    p = subparsers.add_parser(
        "jar", description="Build a topology JAR from a source directory"
    )
    p.add_argument(
        "--src", default="src", help="Directory packaged as resources/ (default: src)"
    )
    p.add_argument(
        "-o", "--output", default=None, help="Output path (default: .artifacts/topology.jar)"
    )
    p.set_defaults(func=main)


def main(args):
    build_jar(src_dir=args.src, output_path=args.output)
```

"""DEPRECATED backward-compatibility shim for the retired `streamparse` package.

Everything here forwards to :mod:`pystorm_a8c` and emits a
:class:`DeprecationWarning`. Nothing new should import from this package.

TODO(pystorm-a8c): remove this entire `streamparse/` package once no consumer

  1. `grep -rn "streamparse" --include=*.py` across every consuming repo
     returns nothing (casterisk-realtime is migrated in Task 14).
  2. Delete this directory.
  3. Drop "streamparse" from `module-name` in pyproject.toml.
  4. Delete test/unit/test_streamparse_compat.py.
  5. Release a MINOR version bump -- removing this is a breaking Python-API
     change, and MAJOR is reserved for the Storm major line (see README).
"""

import importlib
import warnings

#: Public name -> the canonical module it now lives in. Used for the warning
#: message; the object itself is always fetched from the `pystorm_a8c` root.
_MOVED = {
    "Bolt": "pystorm_a8c.bolt",
    "BatchingBolt": "pystorm_a8c.bolt",
    "TicklessBatchingBolt": "pystorm_a8c.bolt",
    "Spout": "pystorm_a8c.spout",
    "ReliableSpout": "pystorm_a8c.spout",
    "Component": "pystorm_a8c.component",
    "Tuple": "pystorm_a8c.component",
    "Topology": "pystorm_a8c.dsl.topology",
    "Stream": "pystorm_a8c.dsl.stream",
    "Grouping": "pystorm_a8c.dsl.stream",
    "StormWentAwayError": "pystorm_a8c.exceptions",
}

__all__ = sorted(_MOVED)


def _warn(old, new, stacklevel=3):
    warnings.warn(
        f"{old} is deprecated and will be removed; use {new} instead. "
        "The `streamparse` package name is a temporary compatibility shim "
        "over `pystorm_a8c`.",
        DeprecationWarning,
        stacklevel=stacklevel,
    )


def __getattr__(name):
    # PEP 562: only called for names not already in module globals.
    if name not in _MOVED:
        raise AttributeError(f"module 'streamparse' has no attribute {name!r}")
    _warn(f"streamparse.{name}", f"{_MOVED[name]}.{name}")
    value = getattr(importlib.import_module("pystorm_a8c"), name)
    # Cache in globals so `from streamparse import X` -- which looks the
    # attribute up more than once -- warns exactly once per symbol per process.
    globals()[name] = value
    return value


def __dir__():
    return list(__all__)

**Making the warning visible.** `DeprecationWarning` is silenced by default outside `__main__`, so it needs help to be useful. Two deliberate non-choices first:

- A blanket `filterwarnings = ["error::DeprecationWarning"]` in `pyproject.toml` is **not** used. On a 3.9-3.14 matrix, third-party deprecations (thriftpy2, stdlib removals) would fail the suite for reasons that have nothing to do with this shim.

```python
def test_nothing_inside_pystorm_a8c_imports_the_shim():
    """The shim is one-directional: pystorm_a8c must never depend on it.

    That property is what makes deleting `streamparse/` a safe, self-contained
    change rather than a refactor. Checked on the AST, not on the file text:
    most of `pystorm_a8c` was ported *from* streamparse, so provenance
    docstrings and comments naming it are expected and harmless. Only a real
    import is a defect.
    """
    import ast
    import pathlib

    root = pathlib.Path(__file__).resolve().parents[2] / "pystorm_a8c"
    sources = sorted(root.rglob("*.py"))
    assert sources, f"found no modules under {root} -- wrong path, test is vacuous"

    offenders = []
    for path in sources:
        for node in ast.walk(ast.parse(path.read_text(), filename=str(path))):
            if isinstance(node, ast.Import):
                names = [alias.name for alias in node.names]
            elif isinstance(node, ast.ImportFrom):
                names = [node.module or ""]
            else:
                continue
            for name in names:
                if name == "streamparse" or name.startswith("streamparse."):
                    rel = path.relative_to(root)
                    offenders.append(f"{rel}:{node.lineno}: {name}")

    assert offenders == [], f"pystorm_a8c must not import streamparse: {offenders}"
```

## Versioning

Plain `MAJOR.MINOR.PATCH`, with one twist:

```
1 . 0 . 0
│   │   └── patch: fixes
│   └────── minor: features AND breaking Python-API changes
└────────── MAJOR: the Apache Storm major version this package supports
```

**The major version tracks Apache Storm, not this package's Python API.**
`1.x` supports Storm 1.x. Storm 2.x support will be released as `2.0.0`.

**Because the major position is spoken for, breaking changes to this
package's own API ship in the minor position.** Read the changelog before a
minor bump, not just before a major one. This is the one thing about our
versioning that will surprise you.

There is no epoch and no local version label. The distribution name
`pystorm-a8c` already distinguishes this package from upstream `pystorm`, so
neither would order or identify anything the name doesn't. The `+a8c.N`
suffixes you may remember belong to the retired `pystorm==3.1.4+a8c.1` and
`streamparse==5.0.0+a8c.1` builds, which were published under the *upstream*
names and needed the marker.

### Pinning

```
pystorm-a8c==1.0.0
```

### Git tags

Releases are tagged `pystorm-a8c-v1.0.0`, not `v1.0.0`. This branch lives in
the `Automattic/pystorm` fork and inherits upstream pystorm's tag history,
which already includes `v1.0.0` through `v3.1.4` — the bare names collide.

**Spec coverage.** Every decision from the requirements is implemented: merge-and-rename to `pystorm-a8c` (Tasks 1-12), shipped from a **branch of `Automattic/pystorm`** rather than a new repo (Task 1 Step 1, Task 13 Steps 7-8); port only actively-used codepaths, established by the cross-repo sweep (the "actively used surface" table drives every port task, and Tasks 4/7/10 each delete specific unused classes); Storm 1.2.x with the 2.x door open (Task 6's facade plus its enforcement test); drop SSH entirely and retire legacy envs (Task 9 removes the tunnel from the library, Task 14 Steps 8-9 delete the `storm3`/`storm-dev3` envs and the whole Fabric surface from casterisk); Python 3.9 floor tested through 3.14 via uv (Task 1's matrix, verified again in Task 12 Step 4); the plain `1.0.0` version scheme in which the major tracks the Storm major line (Global Constraints, enforced by `test/test_version.py` in Task 1, explained in the README in Task 12 Step 5, and verified end-to-end through packaging in Task 13 Step 2).

**Version-scheme consistency.** `pyproject.toml` holds the only literal `1.0.0`; `pystorm_a8c.__version__` is derived from installed metadata, so the two cannot disagree except via a stale install — which `test_version_matches_pyproject` catches explicitly. The remaining checks are mechanical, not disciplinary: `test/test_version.py` (shape, no-epoch/no-local-label guard, Storm-major cross-check against `STORM_IDL_VERSION`), `test/test_dependencies.py` (backend is `uv_build`, version is static not dynamic), the wheel METADATA assertion in Task 13 Step 2, and the casterisk pin in Task 14 Step 5.

**Deliberate breakage, stated rather than hidden.** Task 14 removes Fabric from casterisk-realtime completely, which kills the `fab deploy.topo` route in `deployments/deploy.sh` — the two share a requirements file (`deploy.sh:142`), so the `streamparse` pin cannot leave without taking that route with it. This is intended: `pystorm-a8c` targets only `<nimbus-host>` (`storm4`), which has no SSH or Fabric access, and reaches it through the deployer container's `bin/topo-submit`. The dead branch in `deploy.sh` is a follow-up PR in the `deployments` repo (Task 14 Step 9), not a prerequisite. Task 14 Step 1 re-checks the one assumption this rests on — that no live job still selects `storm3` or `storm-dev3` — before any deletion happens.

**The `streamparse` compat shim, and why it is not a hedge.** Task 12 ships a five-module `streamparse` package that forwards every consumed name to its `pystorm_a8c` home and emits a `DeprecationWarning` per symbol on first use. Three properties make it a migration tool rather than permanent dead weight. It is *one-directional* — nothing inside `pystorm_a8c` imports it, enforced structurally by `test_nothing_inside_pystorm_a8c_imports_the_shim`, so deleting the directory can never break the real package. It is *loud* — every path through it warns, and Task 14 Step 6 runs the casterisk suite under `-W error::DeprecationWarning` so a surviving import fails the build with a file and line rather than lingering. And it is *bounded* — the removal checklist lives in `streamparse/__init__.py`, is restated for downstreams in the README and for operators in Task 15 Step 9, and names its own trigger. Its actual job is narrow: it converts a missed import in Task 14's mechanical `sed` rewrite from a worker that dies at startup in production into a warning in a test log. The cost of carrying it is one directory and five files of no logic.

The shim's one real hazard is that this wheel now owns the top-level name `streamparse` and so can never be co-installed with the real distribution — whichever installs second silently wins. That is why removing the `streamparse==5.0.0+a8c.1` pin in Task 14 Step 5 is mandatory rather than tidiness, why Task 13 Step 4 asserts the smoke venv has no `streamparse` distribution, and why it appears in Global Constraints.

**One behavioral change worth re-flagging at review time.** Removing `ssh_tunnel` would change how `storm3`/`storm-dev3` reach Nimbus — moot, since Task 14 Step 8 deletes both envs. `local` and `storm4` are unaffected either way: they already set `use_ssh_for_nimbus: false`.

**A previously-flagged risk that no longer exists.** Earlier revisions flattened `BatchingBolt` into `TicklessBatchingBolt`, which changed the MRO of ten casterisk bolts — `KinesisStreamWriter`, `HttpPixelRequesterBolt`, `ConversionsWriter`, `KinesisFirehoseWriterBase`, `ElasticsearchWriter`, `DeliveryMetricsRecorder`, `DatadogMetricsRecorder`, `KafkaWriterBolt`, `OpFilter`, `ShareStreamer`. Task 4 now keeps both classes and the upstream `TicklessBatchingBolt(BatchingBolt)` hierarchy, so those ten MROs are byte-identical to pre-migration and there is nothing to re-check. This also made the highest-risk file in the plan a copy-and-fix instead of a refactor, and let the 10 seeded `BatchingBoltTests` be kept wholesale rather than partly deleted and partly re-pointed.

The trade accepted in exchange is ~185 LOC of `BatchingBolt` with no current consumer. It is retained deliberately, for the tick-driven flush option, not by oversight — `test_both_batching_classes_exist_with_upstream_hierarchy` and `test_batching_bolt_is_exported_even_though_casterisk_never_uses_it` exist so that a future reader running a dead-code sweep finds the decision instead of quietly reversing it.
